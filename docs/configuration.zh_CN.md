# 配置与日常使用

产品概览见[首页](../README.zh_CN.md)。本指南补充配置行为、手机热点、NFC、
本地 App 安装与兼容性。网关安装见[插件指南](../tools/openclaw/README.zh_CN.md)，
局域网／公网入口与代理见[网络接入指南](networking.zh_CN.md)。

## 两个 App，按场景选择

无需安装的入口见[网页配置预览](web.zh_CN.md)：支持电脑 USB 配置／刷机，
以及实验性的浏览器蓝牙配置。现有原生 App 继续作为备用入口。

macOS App 通过 USB 完成配置、检测和固件维护；iOS App 是外出时的可选蓝牙
配置工具，不是使用 Passport 的前提。两者读写同一台设备上的配置，不转发对话。
日常使用时可退出 App、断开 USB／蓝牙。使用手机热点时，仅热点需要继续开启，
手机也需在附近；不需要 iOS App 常驻。

## 让 OpenClaw 完成网关接入准备

两个 App 按系统语言偏好使用英文或简体中文，复制的接入提示词也跟随系统；
其他语言回退英文，不另设 App 内语言开关。设备的屏幕语言是独立配置项，
只有主动修改并保存才会改变。

两个 App 的 OpenClaw 配对表单都有「复制提示词」。把内容发给能操作 **OpenClaw
网关主机**的 agent；网关主机可以不是运行配置 App 的这台 Mac。它是交给 agent
执行的接入请求，不是 App 内置的插件安装器或隧道服务。

### 你需要准备什么

- 已运行、已有可用模型的 OpenClaw，以及能在网关主机执行安装与配置的 agent。
  配置 App 可以在另一台电脑上；只有聊天能力、无法操作网关的 agent 不能代为部署。
- Passport、首次安装固件所需的电脑与数据线、可连接的 2.4 GHz Wi-Fi 或兼容手机热点。
  macOS App 支持 macOS 14+；iOS App 可选，需自行签名安装。
- 公网接入所需的隧道服务授权、可用域名／证书及配额；已有入口直接复用。
  缺少资源时按 agent 提示操作，不要求先手动打通入口，也不承诺免登录或免费提供资源。
- 通话需要可用的实时语音服务；只有普通文本模型不代表已经支持通话。
  先完成语音问答也可以，实时服务凭据随后在网关安全配置。

插件、专属 `passport` 助手与公网入口由提示词引导检查并补齐，**不是必须先手动完成的步骤**。

### 复制提示词之后

1. agent 先检查现状，缺少插件时安装本项目兼容的正式版本，并检查专属 `passport`
   助手、语音转写、模型和实时语音配置。已有正常配置直接复用，不在每次配对时重建。
2. 优先复用已验证的公网 WSS 入口；没有则利用已有授权的隧道账户和资源建立持久入口。
   缺登录、域名、证书、配额或模型凭据时，只提示必要操作。新增费用或影响现有资源的
   改动需另行确认；提示词不会自动提供这些资源。
3. 修改前备份，保留设备鉴权与回环监听，仅在安装或配置确实需要时重载／重启。
   检查插件状态、DNS、TLS 和 WebSocket 鉴权后，再生成受限配对码。
   就绪检查不是实机语音验收；通话缺少实时服务凭据时，会与提问状态分开说明。
4. 把返回的地址、配对码填回 App，或在 iOS App 扫码，配好 Wi-Fi 后点「保存配置」。
   配对码也应保密；管理员 token、模型密钥与隧道凭据留在网关，不下发给设备。

手动安装和网络配置见[插件指南](../tools/openclaw/README.zh_CN.md)与
[网络接入与安全指南](networking.zh_CN.md)。如果设备仅在局域网使用，走手动配置，
不必通过这份提示词申请公网入口。

## 配置保存在哪里

Passport 是配置的权威来源，最多保存八套 Wi-Fi、四套助手连接配置、语言和扬声器音量。
App 读取设备状态后编辑草稿。macOS App 也会记住常用表单值和 Wi-Fi 密码，
但这些本机缓存不代表第二份设备配置。

**macOS App 密码缓存不是钥匙串。** 当前保存于
`~/Library/Application Support/AI Passport OpenClaw/wifi.json`，
写入时设为仅当前用户可读写的权限，App 本身不加密。
请把它和系统备份视为敏感信息。在网络行菜单中「忘记」可清除本机记住的密码；
忘记设备已存网络是另一个操作。不要把此文件、配置导出或 NVS 转储附在 issue 中。

网关地址、设备凭据和 Wi-Fi 存在设备 NVS；模型 API key 与服务商配置留在 OpenClaw。
提问固定使用 `passport` agent 和每设备独立会话；助手配置选择连接，不是任意提问 agent ID。
请在该专属 agent 上设置工具与模型权限。有设备即拥有其配置的权限，遗失后应撤销授权。

干净固件没有私人隧道入口、代理节点或模型密钥。公网 NTP、回环地址和配网门户
`192.168.4.1` 是基础设施默认值，不是私人助手地址。
文档和截图使用保留的 `.example`／`.invalid` 地址及虚构网络。

## 保存、撤销与更新

- 点击 **「保存配置」** 前，修改都只是草稿，包括 macOS App 中的语言和音量。
  切换助手时，各助手草稿分别保留。
- 保存依次执行，每步等待确认并重新读取设备，Wi-Fi 最后保存。
  **不是原子事务**：后面的步骤失败，前面已完成的仍已保存，未完成的保留供重试。
- 保存成功、失败和重连都不清空表单。**「撤销修改」** 恢复最后读取或确认的值，
  不会撤销已经完成的写入，也不会恢复已消耗的一次性配对码。
- Wi-Fi 与助手可以独立修改，只改需要变化的部分；不必为了换网络重新配对。
- **「设备维护」** 是独立、显式的 USB 固件操作。保存配置不刷机，匹配的内置固件不会反复写入。
- macOS App 的兼容应用更新写入 `0x10000`，上界为 `0x350000`（不含）。
  首次安装的 `0x0` 合并镜像可能重置 NVS。应用保留 `cardid`、`audio` 分区，
  从其他固件迁移时请先检查分区表。不提供自动恢复原厂固件。
  详见[固件布局与数据策略](development/engineering/firmware-layout.zh_CN.md)。

### 连接检测能说明什么

macOS App 的 **「测试地址」** 从电脑发起；**「检测当前助手」** 使用 Passport 的 Wi-Fi、
路由和配对凭据，检查网关鉴权、提问会话权限和实时服务配置，不录音也不发送问题。
可以中止检测，但检测通过不代表模型回答、麦克风或长通话已验收。
Wi-Fi 测试在 Passport 上执行，不会切换电脑当前连接的网络。

通话、录音和设备检测期间，连接类操作会禁用。旧固件可保留基础配置能力，
但音量同步与设备检测需要更新到声明 `device-control` 的固件。
过期音量写入和忙碌时的变更会被拒绝，持久化成功后才确认写入。

## iPhone 配网与热点

以下是可选的 iOS App 流程；也可以完全通过 macOS App 预先配置手机热点。

1. 在 Passport **设置 → 蓝牙** 中用中间键打开蓝牙。在 iOS App 中选择
   `AI Passport XXXX`，末尾四位十六进制标识设备，重启不变。
2. 点击 **「搜索」**。由 **Passport** 扫描附近 2.4 GHz 网络，不是读取 iPhone 扫描结果。
   选择网络或填写完整 SSID。App 不申请定位、不读取手机当前 SSID，也拿不到 iOS 已存密码。
3. 输入密码并保存。选择设备已存网络时，密码留空会沿用设备已存密码。
   再次选择同名网络保留输入；改选不同名称则清空密码，避免串用。
4. 保存通过蓝牙下发，不切换手机 Wi-Fi。取消扫描、保存失败或重连均保留可编辑内容。

声明 `scan-live` 的固件逐信道返回发现结果，最多 32 个网络名称。
扫描过程中已有行不重新排序，可以提前选中，但保存需等待扫描结束。
旧固件在整轮扫描后返回。列表为空或扫描失败时仍可手工输入。

链环图标来自观察到的 Apple 厂商信息元素，只是尽力识别 iPhone 热点的提示，
不代表确认热点所有者或安全性。未识别的热点仍可作为普通 Wi-Fi 选择，
无 `NET_KIND` 元数据的旧固件无法提供此标记。

### 连接这台 iPhone 的个人热点

- 打开 **设置 → 个人热点 → 允许其他人加入**，开启 **「最大兼容性」**，使用 2.4 GHz。
- 热点名称就是 **iPhone 名称**，不能单独改热点名。扫描选择，或从
  **设置 → 通用 → 关于本机 → 名称** 复制完整名称。手机改名后 SSID 也会变化。
  App 没有 Apple 限制申请的真实设备名称读取权限。
- **找不到本机热点时，请停留在系统「个人热点」页并保持亮屏，再扫描／连接。**
  部分 iPhone 离开此页后停止向非 Apple 设备广播。App 可以在后台接收蓝牙回复。
- 热点密码需首次手工填写。iOS 不允许本 App 读取该密码或静默开启热点，
  以后可复用设备保存的密码。
- App 不提供直达个人热点页的系统链接，测试过的私有设置 URL 无法可靠打开目标页面。

已存网络也可在 Passport 的「设置 → Wi-Fi」里选择并连接。
新增网络、修正密码使用任一 App 即可。设备会区分未发现网络、认证失败、
安全模式不兼容和获取 IP 超时；拒绝配置时不会故意断开蓝牙或清除草稿。

### 不安装 iOS App，也能使用手机热点

1. 在 iPhone 的 **设置 → 个人热点** 开启 **「允许其他人加入」** 和
   **「最大兼容性」**。核对手机名称和热点密码，保持此页打开。
2. 通过 USB 将 Passport 接到电脑，在 macOS App 的 Wi-Fi 区域选择或手工填写
   热点名称、密码，点 **「保存配置」**，等待设备连接成功。
   **当前固件先试连、再保存新网络**；首次配置时热点必须在设备附近且可连接，
   不支持把暂时不可用的新网络仅离线存入。
3. 外出时开启同名、同密码的热点，在 Passport 的 **设置 → 网络** 选择已存热点。
   换回家中或办公室 Wi-Fi 也在这里选择，不需要重配助手。

使用热点不等于网关可达。若 OpenClaw 在家中内网，外出需要已打通并有鉴权的
公网入口，或设备实际可用的私网连接，见[网络接入指南](networking.zh_CN.md)。

## 蓝牙行为与安全

蓝牙待机默认开启。开机后先给已存 Wi-Fi 最多十秒连接，再启动蓝牙；
手动打开无需等待。没有两分钟发现超时，离开配网页也不会关闭。
设置菜单直接显示开关状态，原地切换，无需二级页面。

录音、通话和网关工作期间会临时释放蓝牙内存，配置端因此断连；
音频与网关清理结束后恢复。空闲网关连接可能让出内存给蓝牙，所以下次提问需要重新连网关。
保存配置、切换 Wi-Fi 不会主动关闭现有配置连接。手动关闭后保持关闭，
直到再次打开或设备重启。

手机端要求固件声明 `ble-secure`，旧固件需先通过 USB 更新才能发送密码。
写入需加密连接，回复按 MTU 分包并逐包确认。NVS 保存最多三台配置端的绑定，
正常重连／重启不应再次要求系统配对；遗忘设备或清空绑定后需要重新配对。

**Just Works 加密不验证所有权，也不防主动中间人攻击。**
请在可信环境配置；不可信场景下不需要配网时关闭蓝牙。

## NFC 与个人热点

无源 NFC 标签独立于 Passport 的供电和固件，可以触发 iPhone 自动化，
但不能唤醒 ESP32、配置 Wi-Fi 或认证设备。实测硬件是 NTAG213，用户存储区 144 字节。

### 建立自动化

1. 先用 macOS App（USB）或 iOS App（蓝牙）把热点 SSID 和密码配置给 Passport。
2. 打开 **快捷指令 → 自动化 → NFC**，扫描 Passport 并命名触发器。
3. 系统支持时选择 **「立即运行」**，添加 **「设定个人热点 → 打开」**，
   可接上 **「打开 App → AI Passport」**。使用系统「打开 App」动作，
   当前 App 没有注册专属 App Shortcuts。
4. 手机亮屏时测试。没有动作，先检查自动化是否启用、确认／通知设置和动作权限。
   部分 iOS 组合仍需要点击通知或解锁。

Apple 的 [NFC 触发器说明](https://support.apple.com/guide/shortcuts/apde31e9638b/ios)
介绍标签识别，[自动化说明](https://support.apple.com/guide/shortcuts/enable-or-disable-a-personal-automation-apd602971e63/ios)
介绍自动执行。实际行为仍受 iOS 和运营商规则影响。

### 去掉原厂网址提示

NDEF 中有 URL 时，即使已经建立 NFC 自动化，iOS 仍可能弹出网页横幅。
维护者在自己的设备上 **把 URL 替换为唯一的 `AI Passport` 文本记录** 后，
网页提示消失，热点自动化在实测环境中正常工作。

- 用兼容的 NFC 写入工具，例如 iPhone NFC 写入 App 或 Proxmark 命令行工具。
  本项目 macOS App 不包含 NFC 写入功能。
- 先读取并私下备份原始 NDEF；出厂网址可能带有设备专属秘密。
  不要公开备份、UID 或原始完整 URL。
- **替换 URL，不是追加记录。** 只改 NDEF 用户内容，保留 UID、能力容器、
  锁控制数据、锁定位及配置，不要永久锁定标签。
- 写完读回，确认没有 URL 记录。UID 不变，原有 NFC 自动化通常仍可识别。
- 标签已锁定或工具不支持时应停止，不要强行写入。USB 刷机无法重写无源标签。

这是实测有效的可选技巧，不保证所有 iOS／标签组合。打开 AI Passport 不会自动完成
蓝牙配对、切换网络或保存配置。NFC 内容可公开读取和复制，
不要写入 Wi-Fi 密码、配对码、网关 token 或 API key。

## 运行 iOS App

当前不通过 TestFlight 或 App Store 分发。下载
[Release](https://github.com/vangie/ai-passport-openclaw/releases) 的 iOS App 源码包，
或使用本仓库，两者均含 `ios/` 与 `shared/`。安装完整 Xcode 和 XcodeGen 后：

```sh
cd ios
xcodegen generate
open Passport.xcodeproj
```

选择自己的签名团队和已连接的真实 iPhone，运行 `Passport` scheme，
按 Xcode 提示在手机上信任开发者、开启开发者模式。Personal Team 签名用于本地开发，
可能过期；不要提交证书或签名账号配置。模拟器只能看界面，
不能连真实蓝牙设备或 PassportSim 的虚拟无线电。

```sh
xcodebuild -project ios/Passport.xcodeproj -scheme Passport \
  -destination 'platform=iOS Simulator,name=iPhone 17' test CODE_SIGNING_ALLOWED=NO
```

生成工程后从仓库根目录运行上述测试。macOS App 用 `make sim-mac` 构建，
可在本机环境设置 `DEVELOPMENT_TEAM`。
主机检查需要[构建指南](development/engineering/build-and-test.zh_CN.md)中的工具，
包括 mbedTLS 与 cJSON 源码；固件使用 ESP-IDF 5.5.3。

## 待机与兼容性

- 满足空闲条件 60 秒后熄屏，**不是关机**。第一次按键只唤醒，第二次才执行屏幕所示动作。
  通话、录音、设置、配置任务和已枚举的电脑 USB 连接会保持唤醒。
- USB 主机不等于可靠的充电检测。接普通充电器仍可能熄屏，但不停止充电。
  电量百分比不代表充电状态，电池续航需要实测。
- 产品命名为 `Passport`，iOS Bundle ID 为 `ai.mirasim.passport`。
  NVS 设置命名空间为 `passport`、身份为 `passport_id`，序列化设置以 `PSP1` 开头。
  不迁移未发布原型的旧身份。
- 配网 AP 为 `Passport-Setup`／`passport-setup`。蓝牙服务标识不变；
  旧原型 App 可能并存，需手动移除。
- 提问会话名为 `agent:passport:passport-<device-id>`。屏幕最近聊天在 RAM 中，
  不是持久聊天记录，也不是网关的上下文存储。

麦克风、网络、识别和长通话需要真实硬件验收，构建成功或模拟器截图无法证明这些能力。
