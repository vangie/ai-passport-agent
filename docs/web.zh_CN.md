# 浏览器配置台

正式地址：<https://ai-passport-agent.codelife.me/>。
仓库的 Pages 地址 <https://vangie.github.io/ai-passport-agent/> 会跳转到该自定义域名。

### 旧地址兼容

保留 `ai-passport-openclaw.codelife.me` 作为兼容入口，不维护第二套配置台。
DNS 主机记录为 `ai-passport-openclaw`，类型 `CNAME`，记录值为 `vangie.github.io`，
TTL 保持默认；新域名的解析不要改。仅恢复 DNS 不够：每个 GitHub Pages 站点只支持
一个自定义域名，旧域名需要单独绑定一个站点。

独立仓库 `vangie/ai-passport-legacy-site` 只托管静态跳转页，`CNAME` 文件绑定旧域名，
证书签发后开启 HTTPS。运行 `python3 tools/legacy_site.py` 生成部署文件，
将 `build/legacy-site/` 的内容发布至该仓库的 Pages 源；不要覆盖主配置台或修改其域名。
跳转源码位于 `tools/legacy-site/index.html`，同时生成为 `404.html`，兼容旧深层链接。
通过 `location.replace` 跳转，避免返回键循环；保留路径、查询参数与片段，
不加载第三方资源、不做统计，禁用脚本时仍有中英文入口链接。
这是浏览器跳转，不是供固件下载客户端使用的 HTTP 重定向；新配置台依然直接提供固件。

必须同时恢复旧 DNS 和有效 HTTPS 证书，旧书签才可正常访问；已打开旧网页的用户需刷新。
设备里的 Wi-Fi、助手凭据和固件均不受影响。USB／蓝牙浏览器授权与网站来源绑定，
新地址可能需要重新授权设备，但不必因为网站搬迁而清空配置或重新配对。
旧域名 DNS 指向 GitHub Pages 期间，应持续保留该域名和跳转站点的绑定，不要先删除绑定。

已验证的历史固件身份保留在 `web/release-builds.json`，不依赖旧 Release 下载是否仍然存在。

静态网站作为新的主推配置入口，macOS App / iOS App 仅保留源码，CI 不再构建，
新 Release 也不再提供原生 App 包。
不需要账户、数据库或配置后台，设备仍是配置的唯一数据源。
语音由 Passport 直接交给已配置的 Agent，不经过网页或网站托管服务。

页头将项目既有图标、AI Passport Agent 项目名和页面标题合并为一行，语言开关放在同一行。
窄屏隐藏重复的品牌文字，不再另占一行标题；浏览器标签页也使用同一项目图标。

未连接时，「连接设备」与 USB／蓝牙按钮保持在同一行，窄屏也不折行。
浏览器兼容提示和连接反馈仅在需要时显示于下方，不常驻操作说明段落。

页头语言开关同时显示「中 / EN」，滑块标出当前语言，可点击切换，聚焦后也可用方向键。
这里只切换网页语言；设备屏幕语言需在「设备偏好」中单独保存。切换语言不会清空当前输入。

## 本地启动

需要 Node.js 22.12+ 或 24，以及 Python 3：

```sh
make web
```

浏览器将 `http://localhost` 和回环地址视为可信上下文，本机测试不必配置 HTTPS
证书。不支持直接双击打开 `index.html`。手机通过普通局域网 IP 打开电脑的 HTTP
地址不享受这个例外，需要可信 HTTPS。

`make web` 在同一个前台进程中管理静态服务和隧道；未安装 `cloudflared` 时只启动本地
服务。Ctrl+C 一并停止两者。服务器仅监听回环地址，只提供 `web/dist`，不暴露仓库或
Vite 开发服务。优先使用端口 4173，被占用时自动选取空闲端口，不中断已有服务，
也不把已有服务转到公网。访问命令输出的本地或 HTTPS 地址即可。

网站只有 `make web` 这一个 Make 入口。保持首次启动的终端运行，改完代码后再次
执行同一命令：重新构建、复用现有服务和隧道、再次输出相同地址，然后退出。
刷新页面即可看到修改。并发执行时构建会串行处理，只有一个进程持有预览服务。
新文件先独立构建，再逐个替换，入口页面最后切换；旧资源保留，已打开的页面仍可
访问。构建失败不会替换正在工作的预览。不需要记忆额外的启动、状态或构建命令。

Quick Tunnel 进程重启后会分配新地址，缓存旧地址不能将它固定。所有隧道连接中断时，
启动器会清除公网地址；连接重新注册后才恢复显示。如果 Cloudflare 明确提示临时隧道
已不存在，启动器在本地服务保持运行的同时最多重建两次，每次会产生新地址。
再次运行 `make web` 可查看当前地址。命名隧道不会被自动替换成临时隧道。

希望重启后也复用同一地址，需要在自己的 Cloudflare 账户一次性配置专用命名隧道和域名：

```sh
cloudflared tunnel login
cloudflared tunnel create ai-passport-web-dev
cloudflared tunnel route dns ai-passport-web-dev passport-dev.example.com
```

在仓库外创建 `~/.config/ai-passport-agent/web-tunnel.json`。
新路径不存在时，仍会读取旧的 `~/.config/ai-passport-openclaw/web-tunnel.json`：

```json
{
  "tunnel": "00000000-0000-0000-0000-000000000000",
  "hostname": "passport-dev.example.com",
  "credentials_file": "~/.cloudflared/00000000-0000-0000-0000-000000000000.json"
}
```

域名换成自己在 Cloudflare 管理的子域名，UUID 和凭据文件路径使用 `tunnel create`
返回的值。之后 `make web` 自动优先使用这个命名隧道，重启地址也不变。
可用环境变量 `PASSPORT_WEB_TUNNEL_CONFIG` 指向另一份 JSON 配置。
固定配置错误时明确报错，不悄悄换成临时公网地址。凭据必须在仓库外，启动脚本不会
自动改 DNS、安装后台服务或修改其他隧道。

只有配置的域名转到预览，其他域名返回 404。地址和进程锁记录在被 Git 忽略的
`build/`，不会放入 `web/dist`。两种隧道的地址默认都是公开的；需要限制访问时，
自行配置 Cloudflare Access。不同网络的可达性仍可能不同。
隧道只提供网页，不传输 USB／蓝牙数据，也不代理 OpenClaw，不要在不可信的网页
副本中输入真实凭据。参见 Cloudflare 的
[Quick Tunnel 限制](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/) 和
[命名隧道配置](https://developers.cloudflare.com/tunnel/features/local-management/create-local-tunnel/)。

## 连接和配置

网页自动检测 Web Serial 和 Web Bluetooth 能力，不按浏览器名称猜测。支持时不显示
兼容性说明；Bluefy 等仅支持蓝牙的浏览器隐藏 USB 连接入口，固件模块只保留一句
「固件更新请在电脑上通过 USB 完成」。其他不支持的连接方式会禁用，并在对应按钮旁
说明原因。不安全地址显示一条 HTTPS／localhost 提醒。能力检测不会主动申请设备权限，
支持 Web Serial 的浏览器仍保留完整的固件更新操作。

配置页只通过 USB 或蓝牙连接真实设备，不提供配置示例入口或虚拟设备模式；
虚拟数据仅用于自动化测试。未连接时无法读取、扫描或保存配置，仍可通过 USB
执行完整固件安装。

1. 电脑用 Chrome / Edge 打开网页，选择「USB 连接」和设备串口；先关闭占用串口的
   原生应用或监视器。蓝牙配置需要实现 Web Bluetooth 的浏览器，并在设备空闲时进入
   Passport「设置 → 蓝牙」开启蓝牙。支持 `ble-takeover` 的固件连接后仍可被发现，
   新端订阅并发送加密 `HELLO` 后接管；旧端已执行的命令先完成并确认，尚未执行的
   旧会话命令会被拒绝。旧端保留草稿，不自动抢连。只有一个配置端可操作设备，
   第二个连接位仅用于接管，未完成握手两分钟后释放。旧固件需先在手机 App 断开再
   扫描；仅配对过不影响发现，无需删除配对。iPhone Safari 和微信内置网页不支持；Bluefy 是待真机
   验收的候选方案。
   Mac 扫描列表为空时，在「系统设置 → 隐私与安全性 → 蓝牙」检查当前使用的浏览器
   是否获准，再重新打开浏览器；USB 可用不代表蓝牙已获准。更新网页后关闭旧扫描窗口，
   重新连接。发现设备时同时支持配置服务 UUID 或 `AI Passport ` 名称前缀，连接时仍
   校验实际 GATT 配置服务。
   蓝牙说明仅在点击「蓝牙连接」后显示于连接卡片下方，初次打开或选择 USB 时不显示，
   连接成功后收起。已有权限仍搜不到时，展开「找不到蓝牙设备？」。先记下未保存的内容，再完全退出并
   重开浏览器，不是刷新网页。Chrome 可在地址栏输入 `chrome://restart`，重启后重新
   打开此页连接。仍找不到设备时，选择「兼容扫描：显示所有蓝牙设备」，
   在列表里选择 AI Passport 加四位编号的设备。兼容扫描仅取消发现过滤，发送命令前仍
   必须找到配置服务；不必先重刷固件、清空设备配置或重置所有系统蓝牙配对。
2. 页面读取已存 Wi-Fi、助手和设备偏好。让 Passport 扫描附近 2.4 GHz 网络，或手动
   填写名称。只有已存网络或明确无密码网络可以留空密码。测试连接可能切换 Passport
   网络，不会切换电脑的 Wi-Fi。
3. 在「新增助手」中先选 OpenClaw 或 Hermes，再复制对应提示词给能操作该网关主机的
   Agent，粘贴返回的配对码或二维码
   JSON，填写助手名称。地址不一致时拒绝保存，不静默覆盖。首版不含相机扫码。
4. 每个助手在列表中显示连接方式，点击该条目的「连接设置」原位展开直连／Shadowsocks
   配置。编辑另一助手不会将它设为当前；未保存的连接修改标记在所属助手上，切换编辑
   对象前会确认。按需修改屏幕语言、音量，统一点击「保存配置」。
   当前固件仅支持 `aes-256-cfb`，不回读密码。多组修改依次写入，并非原子事务：
   后一组失败时，前面已成功的组不会回滚。
5. 保存、报错或断线均保留输入；「撤销修改」才主动丢弃草稿。忘记网络、删除助手和
   设为当前立即生效。配置与密钥不上传配置服务器，也不存入浏览器持久存储。

悬浮保存栏只在按钮旁显示一个状态。保存成功后显示「已保存」，不再追加第二行或撑高
保存栏；再次修改即恢复未保存状态。错误和部分保存的说明允许换行，确保窄屏也能读全
恢复操作。

助手类型只决定配置提示词；切换不会清空已填的名称、地址、配对码，也不会修改设备
已存设置。提示词随网页语言切换：OpenClaw 使用其插件和二维码命令，Hermes 使用
外置平台插件、活动 profile 和专用配对工具。Hermes 需要兼容的预览固件与插件源码，
v0.7.0 包含此功能，v0.6.0 不包含。设备在认证连接后识别后端，与助手的显示名称无关。

复制反馈只出现在「复制配置提示词」按钮旁，不显示为整页通知。
成功时按钮短暂显示勾选图标与「已复制」，旁边提示下一步；读取或剪贴板错误也在原位置
说明并允许重试。复制不会重绘表单、改变设备连接或丢弃输入。

网页不能读取系统钥匙串密码，不能静默开启个人热点或读取热点密码。
若找不到本机 iPhone 热点，请开启「允许其他人加入」和「最大兼容性」，进入系统
「个人热点」页并保持亮屏。切换系统设置时蓝牙连接的后台行为需要真机验证。

## 隐私与数据

页脚的「隐私与数据」入口按需展开完整说明，不打断配置流程，也不在各张卡片中重复提示。
这是一个静态单页应用，没有配置后台；Wi-Fi 密码、代理密钥、网关地址和配对码通过 USB
或蓝牙直达 Passport。草稿只临时保留在页面内存中，方便修改重试，不写入浏览器持久存储；
保存后的配置留在设备上。说明同时区分设备所用的 OpenClaw／语音服务，并注明静态托管方
可能保留常规访问日志，避免把「无配置后台」误解为所有服务都不会处理数据。

## 固件不走运行时 Release 跳转

紧凑的固件卡片并排显示设备版本与可安装版本，标题旁标注 USB。
固件卡片只保留一个右对齐的主按钮。版本区域两列等宽，竖向分隔线位于卡片正中。
设备偏好的语言与音量在连接并读到设备配置前置灰、禁用；断开后重新禁用，保留未保存的修改。
固件未提供音量配置时，音量滑块保持禁用。
「保留配置」始终显示、默认勾选；「更新固件」需通过 USB 读取设备后才能使用，
不会在勾选保留配置时自动改为完整安装。
首次安装或恢复只需取消勾选，使用同一个主按钮「安装固件」；无需已连接配置服务，
也没有单独的恢复入口。页面显示覆盖 Wi-Fi 和助手配置的警告，写入前需确认。
每次成功连接新设备后，恢复为默认勾选，避免沿用上一次的覆盖选择。
蓝牙连接仅启用设备偏好，固件按钮与「保留配置」保持禁用，需换用 USB 连接。
网站未提供内置固件时，安装按钮保持禁用。

网页依赖全部本地打包。CI 在构建时下载正式 Release，核对发布清单中的长度和
SHA-256，把两个固件及清单放入网站自己的 `firmware/` 目录。
用户浏览器从网站同源加载，不请求 GitHub Releases、S3 或第三方 CDN。
GitHub Pages 域名本身仍可能慢或不可达，临时 Cloudflare 地址也不能保证可达。

本地可以使用已下载的正式 Release：

```sh
python3 tools/web.py firmware --from-release RELEASE文件目录
make web
```

目录需含 `release-manifest.json`、`FoloToy-AI-Passport.bin` 和
`FoloToy-AI-Passport-full.bin`。生成副本被 Git 忽略。
缺少固件时仍可构建配置页，但不能使用内置固件刷机。
网页仅安装内置的本项目发布版；自定义固件留给开发者通过命令行写入。
普通更新保留配置；首次安装或恢复时，取消勾选「保留配置」，再点击「安装固件」，
无需已建立 USB 配置连接。
写入前还需明确确认覆盖已存配置。

网页在内部完成设备构建标识与版本的对应。CI 校验最近最多 12 个正式版的镜像及发布
清单（旧版使用 SHA-256 校验列表），将版本索引随网站打包，无需用户浏览器再查询历史。
已知旧版显示「有新版本可更新」；
与网站固件一致时显示「已是最新版」，仍可通过「更新固件」重新安装。设备版本较新时，不把安装旧版
说成升级。未识别版本的固件显示「暂未识别」，不再用「已安装」代替版本号。
按钮统一显示「更新固件」，目标版本在上方展示；替换开发版和降级的警告保留在确认对话框内。
原始构建编号收进默认折叠的「版本详情」。

`make web` 会校验本地归档应用的散列和嵌入的 ELF 标识，自动识别开发版。预览索引只
包含规范化的基础版本、开发版类型和构建标识，不包含任意描述文本、本地路径或设备配置。
开发版使用相同的「更新固件」按钮，并在确认时说明切换后可能缺少开发中的功能；不会替换网站内置
正式固件，也不会把开发固件误标成正式发布版。正式发布准备时会清除本地开发版索引。

保留配置的应用升级需先成功通过 USB 读取设备，校验 ESP32-C3 镜像头和设备当前
分区表，仅写 `0x10000..0x34ffff`，保留 NVS、Card ID 和音频数据。
首次安装／完整恢复将内置合并镜像写到零地址，会覆盖配置，需单独确认；两种模式均不
整片擦除。下载文件在设备复位前校验散列，刷完还比对设备 MD5。写入中不要拔线。
网页刷机和蓝牙兼容性仍需真机验收，虚拟设备自动化测试通过不代表硬件测试通过。

## GitHub Pages

`.github/workflows/web.yml` 运行协议／浏览器测试，准备最新正式固件，部署静态网站。
PR 只测试和构建；main 的相关推送、手动触发和正式 Release 发布会部署。
成功的标签 Release 工作流完成后也触发部署，覆盖使用 GitHub 工作流令牌发布的情况。
不需要运行时后台或保存部署密钥。Pages 构建来源设为 **GitHub Actions**；
相对资源路径支持仓库子目录。

`main` 上的 `web/`、共用配对提示词、图片以及网页构建／隐私检查工具有变更时，
测试通过后自动发布。部署先检查源码中的私有地址并运行 Gitleaks，再检查实际上传的
静态产物。产物白名单排除本地配置、日志、源码映射和调试文件；固件检查拒绝设备已存数据
和本地开发版索引。检查失败则不发布。仅上传 `web/dist`，不上传工作目录、
本地预览隧道配置、浏览器草稿或开发者凭据。

源码和固件散列处于同一个网站信任边界，散列防损坏，不防发布者被入侵。
不加载第三方脚本、统计，也不把密钥写入 URL。
OpenClaw 公网入口与鉴权独立维护，见[网关连接](networking.zh_CN.md)。
