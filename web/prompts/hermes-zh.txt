请在运行 Hermes 网关的主机上，帮我把 AI Passport 接入现有的个人助手，支持「提问」和「通话」，并生成配对码。请实际检查和完成配置，不要只提供教程。不要套用 OpenClaw 的插件、专用 agent 或配对命令。

授权边界：可以安装缺少的本项目外置插件、补齐当前用户的配置，并使用本机已有资源建立安全、持久的公网入口。先检查并复用正常的部署；改动前备份到仓库外的私有位置。不覆盖其他平台、助手人设、模型、记忆或会话，不放宽工具权限，不改 Hermes 核心，不自动升级，不删除数据，不购买资源。重启只走正常网关生命周期，确认没有重要任务或通话后进行；不要启动占用相同配置目录的第二个网关。缺少登录、凭据或资源时，只提出最小必要操作。

1. 确认当前 Hermes 环境
确认实际运行的网关、Hermes 版本、活动 profile/home、托管 Python 和现有模型、语音转写服务。项目源码是 https://github.com/vangie/ai-passport-agent，先阅读匹配版本的 tools/hermes/README.zh_CN.md 和 docs/networking.zh_CN.md。Hermes 需要 v0.7.0 或更新版本；v0.6.0 不包含它。优先用匹配 Release 的版本化 ai-passport-hermes 包，核对 SHA256SUMS.txt 与 release-manifest.json。核实所选版本确实包含 tools/hermes 及兼容的完整固件，不要捏造 Release 下载地址，也不要把旧版宣称为支持 Hermes。需要预览代码时仅使用已审查的固定版本，记录实际完整提交，不追踪浮动源码自动升级。

2. 安装或检查外置插件
把所选版本完整的 tools/hermes 目录放到活动 Hermes home 下的 plugins/ai-passport-hermes，保留原有配置和配对数据。使用该活动 profile 对应的正常 Hermes 命令运行：
hermes plugins doctor <实际插件目录> --ci
hermes plugins enable ai-passport-hermes
依赖由 Hermes 正常插件安装流程管理，不擅自改核心 Python 环境。按插件文档，在活动 config.yaml 的 gateway.platforms.ai_passport 中启用平台，extra.host 设为 127.0.0.1，选择空闲的本地端口（默认 18790），speech_language 设为 zh。不要改全局语音语言或覆盖现有平台。
「提问」使用当前 Hermes 的个人助手、模型、工具、记忆和设备独立会话，不需要另建名为 passport 的助手。保留用户的助手名称，不把 Hermes 平台名称当作其昵称。
「通话」按文档配置 extra.realtime，使用账户实际可用的实时语音模型、声音和凭据；普通对话由实时语音服务响应，需要工具、实时信息或个人上下文时交回同一 Hermes 助手。模型密钥只从主机已有环境变量或仓库外权限为 0600 的私有文件读取，不写到工牌或回复中。不凭空承诺模型访问权限或免费使用。分别核实提问与通话就绪；仅提问可用时可继续配对，但明确通话尚未配置。

3. 准备安全的公网入口
优先复用证书有效、稳定可达的 wss:// 入口；没有则按项目联网文档，用本机已登录的隧道服务、现有域名和证书建立持久入口，不以临时随机地址替代。将入口转发到插件实际监听的 http://127.0.0.1:<实际端口>，保留 / 和 /passport/v1 路径及 WebSocket 升级。不要公开 Hermes 自身 API，也不要将插件绑定到公网或所有网卡。普通 TCP 隧道改成 wss:// 前缀不等于拥有 TLS。保留设备签名、一次性配对和认证；不得关闭证书校验、允许匿名访问、使用通配信任或依赖设备无法完成的浏览器登录。

4. 验证并签发配对码
核查插件载入、提问模型和转写、实时语音模型及凭据，并检查真实公网 DNS、TLS、WebSocket 升级和认证挑战。插件 doctor 通过不等于模型或设备语音测试通过；无法进行外部网络或实机测试就说明限制，不能以 HTTP 页面可访问代替验证。
在插件就绪后，使用网关的活动 Hermes home 及对应的 Python 运行时执行，替换实际路径和已验证的完整公网 WSS 地址：
python3 <实际插件目录>/passport_auth.py --home <活动 Hermes home> pair --url '<已验证的公网 WSS 地址>'
从成功的 JSON 输出读取 gatewayUrl 与 setupCode；不要使用 openclaw qr，不编造配对码。按实际签发有效期使用，过期重新签发。配对码是敏感的一次性凭据，只在本私密对话返回，不发送到第三方二维码服务。模型密钥、隧道令牌、证书私钥、配置备份和原始日志都留在仓库外的私有位置。

完成后简短返回：

3. 实际网关地址、实际配对码，以及已有个人助手的显示名称（如能确认）。实际值不要加尖括号。若未就绪，报告已完成项、具体阻碍及最小必要操作，不假装成功。
