# Assets

This directory stores reusable fonts, images, music, sound effects, and battery profiles, organized by asset type.

Keep each asset in the matching subdirectory and document its destination, naming, integration method, and source/license. Do not mix binary assets with Markdown documentation.

## Fonts

Store reusable font files and generated font sources in `fonts/`.

- Use descriptive names that include the family, weight, size, and format when relevant.
- Document the source, license, character range, conversion command, and expected destination.
- Check Flash and internal-RAM impact before adding a font; the ESP32-C3 has no PSRAM.
- Do not commit fonts whose license does not permit redistribution.

`fonts/passport_font_16.c` is the application's compressed, 2-bpp Noto Sans SC font at 16 px, covering ASCII, U+00B0 (°), U+00B7 (·), U+2103 (℃), U+3000–3020, U+4E00–9FFF and U+FF00–FF60. It is compiled into the application and selected by the screen labels. Noto Sans SC uses the SIL Open Font License in [`fonts/OFL.txt`](fonts/OFL.txt); the source family is maintained at [Google Fonts](https://github.com/google/fonts/tree/main/ofl/notosanssc). Recreate it with `lv_font_conv@1.5.3 --font PATH_TO_NotoSansSC.ttf --range 0x20-0x7e,0xb0,0xb7,0x2103,0x3000-0x3020,0x4e00-0x9fff,0xff00-0xff60 --size 16 --bpp 2 --format lvgl --no-kerning --lv-include lvgl.h --lv-font-name passport_font_16 -o assets/fonts/passport_font_16.c`. Alternatively, run `python3 tools/make_font.py PATH_TO_NotoSansSC.ttf` to use the pinned converter and character ranges. Compression and large font offsets must be enabled in LVGL. Characters outside those ranges, including emoji, are not guaranteed.

`fonts/passport_font_20.c` is a compressed 2-bpp Noto Sans SC headline subset at 20 px. It covers ASCII and the fixed headlines listed in `tools/make_font.py`; arbitrary replies and names continue to use the complete 16 px application font. Both sizes share the Noto SIL OFL license and are regenerated by that script.

The 16 px reply font also includes the explicit `PUNCTUATION` inventory in `tools/make_font.py`: common Chinese sentence marks, straight/curly/corner quotes, parentheses, square/curly/lenticular/tortoise-shell brackets, book-title marks, hyphens, dashes, horizontal ellipses, middle dots, bullets, slashes, separators, tildes, underscores, reference marks, percent/per-mille signs, and prime marks. It includes common arrows, check/cross marks, arithmetic, comparison, infinity and star symbols so replies and status labels do not fall back to boxes. It includes fullwidth and small-form variants, including U+2010–2017, U+2018/U+2019, U+201C/U+201D, U+2022/U+2025/U+2026/U+2027, U+2030–2037, U+203B, U+22EF, U+3030, and selected U+FE4B–FE5E symbols. Use `python3 tools/make_font.py PATH_TO_NotoSansSC.ttf` to include the entire maintained inventory rather than regenerating from the base ranges alone. `make preview-ui` checks every inventory glyph through the actual reply label's font, verifies a known unsupported emoji remains unsupported, and renders every punctuation page in both interface languages. Reply pagination keeps opening quotes/brackets with their following text and avoids starting a line with closing quotes/brackets.

### Product screenshot provenance and privacy

The web screenshots and three firmware product captures were refreshed on
2026-11-14 using the current screen implementation and synthetic device/browser
transports. `web-desktop.png` and `web-mobile.png` show the website, not native apps;
the mobile capture is a browser-layout demonstration, not an iPhone photograph.
`tools/community_materials.mjs` composes inspected 3:4 community posters from these
captures. All project artwork uses the repository license. Older native-client
images remain archival assets and are no longer linked from the product README.

The screenshots were refreshed on 2026-11-11. Native app previews used temporary
isolated builds with synthetic transport/network state and separate example
bundle identifiers, not a connection to the maintainer's device or Wi-Fi cache.
Firmware previews used the real screen implementation, fonts, icons and RGB565
rendering with demo state. `make preview-ui` runs the maintained screen checks;
these curated product captures use the same renderer with coordinated demo data.

Fixtures use `Passport Home`, `Passport Office`, `Demo iPhone`, a fictional
assistant and `wss://gateway.example`. Passwords are demo-only, masked or absent;
no real pairing codes, proxy nodes, endpoint hostnames or device identities were
used. The image files have metadata stripped and were visually reviewed. These
are UI previews, not hardware acceptance evidence. Do not replace them with
unreviewed screenshots of a configured personal device.

- Use descriptive names and document dimensions, pixel format, conversion steps, and destination.
- Prefer formats suitable for the 240 × 320 RGB565 display and account for Flash and internal RAM.
- Preserve editable sources where licensing permits, and record the source and license.
- Never commit device QR secrets, credentials, or personal data in images.

## Music and sound effects

Store reusable music and sound-effect sources in `music/`.

- Document the source, license, sample rate, bit depth, channels, conversion command, and destination.
- Prefer 16 kHz, 16-bit mono PCM when it matches the current BSP audio path.
- Check Flash and internal-RAM cost before embedding audio; stream or chunk long recordings.
- Do not commit media without redistribution permission.

## Speech detection fixture

[`audio/vad-speech.wav`](audio/vad-speech.wav) is the unchanged
`tests/data/audio_tiny16.wav` fixture from
[libfvad](https://github.com/dpirch/libfvad/tree/532ab666c20d3cfda38bca63abbb0f152706c369),
pinned at `532ab666c20d3cfda38bca63abbb0f152706c369` alongside the WebRTC VAD
core in `components/passport_vad`. It is 16 kHz, 16-bit mono PCM, 180,590 bytes;
no conversion was applied. SHA-256:
`551d3f0282c5d5e1e32e76da97bd3532c38e6f4bb02a32510caf562d7c06ae9c`.
The upstream [BSD license](../components/passport_vad/LICENSE),
[patent grant](../components/passport_vad/PATENTS) and
[authors](../components/passport_vad/AUTHORS) are retained and included in firmware
release notices. The fixture is used only by host tests, not embedded in firmware.
Project-specific rate adaptation, confirmation, endpointing and live gating wrap
the unchanged upstream core. See [speech filtering](../docs/configuration.md#speech-filtering).

## Battery profiles

[`battery/wanli-500mah-profile2-xil40x-20261020.txt`](battery/wanli-500mah-profile2-xil40x-20261020.txt)
contains the supplied CW2017 profile for the Wanli New Energy 500 mAh cell
(profile2, XIL40X, 2026-10-20). It is an unchanged copy of the project-supplied
file, retained at the maintainer's request for this firmware update. Its
original filename is recorded in the paired Chinese document. No separate
license was included in the supplied file.

The format is 80 lines of two hexadecimal digits, one byte per line in register
order. The BSP embeds those bytes in `components/bsp/src/bsp_battery.c`; the
host gate checks the source file and initializer for an exact match. Text-file
SHA-256: `7ea96eba4634f4495a37c25ffacd54c1deaa0693b162c892d671a2ba68460919`.
Decoded 80-byte SHA-256:
`fa7365671093ef449c5bdcfb4adb279e3d275f888109f50b6b2f21e9b96220d5`.
This is a fuel-gauge profile, not a charging configuration or a generic profile
for every 500 mAh cell; see the [hardware guide](../docs/hardware-design/AI_HARDWARE_DEVELOPMENT_GUIDE.md#9-cw2017-fuel-gauge).
