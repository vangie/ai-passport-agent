# AI Passport Agent — Hermes 插件

这是一个**实验性的“提问”和“通话”平台插件**，不是 Hermes 分叉，也不是另外做一个只连
模型的聊天机器人。经过签名认证的设备问题进入 Hermes 原生网关，使用已配置的个人
Agent、工具、记忆、会话存储和授权策略。每台设备都有独立的对话。

现有 OpenClaw 接入保持不变，提问和通话沿用既有设备协议。新版固件还会从认证成功的
网关识别 Hermes，显示平台名称和官方图标；已配对设备在下次连接成功后自动迁移，
无需重新配对。
通话使用主机上的实时语音模型处理日常对话，需要工具、实时信息和私人上下文时，
委托给同一个原生 Hermes Agent。
此实现包含在 v0.7.0；v0.6.0 不包含此实现。

## 前提与安装

- 已有能够正常对话的 Hermes 网关，已配置模型和语音识别。
- 已测试版本：Hermes v0.22.6+481，提交
  `c314285f077e91937c995d419b9fa40af9eb4981`。
- 升级检查：Hermes v0.23.1，提交 `3b421578588243f920886e6fe79a6faa87ea026e`，
  核心工作区干净、外置插件发现与真实运行时适配器测试均通过；维护者随后确认
  v0.7.0 发布前的实机回归已通过。
- `plugin.yaml` 已声明带版本上限的 Python 依赖。由 Hermes 包管理器管理依赖，
  不要直接修改其受管理的 Python 环境。

使用 v0.7.0 中的 `ai-passport-hermes-0.7.0.tar.gz`，先核对 `SHA256SUMS.txt`
与 `release-manifest.json`；旧版 v0.6.0 不包含 Hermes。
压缩包只有 `ai-passport-hermes/` 一层目录，内容仅代码、文档和许可。

将整个目录复制到 `<active-hermes-home>/plugins/ai-passport-hermes`。插件位于
Hermes 安装目录之外，常规升级核心不会覆盖它。替换已安装版本前，通过正常网关
生命周期停止该平台；不要热替换正在运行的传输，也不要用第二个进程打开相同档案库。
设备授权与请求记录在 `<active-hermes-home>/passport/`，不在插件或核心目录；维护前备份该私密目录。
未来 API 兼容性并无保证：核心升级后运行插件 doctor 与适配器测试，再验收提问／通话。
保留已验证的旧插件包以便回退，不要删除授权或从浮动分支自动升级插件。

```sh
hermes plugins doctor <active-hermes-home>/plugins/ai-passport-hermes --ci
hermes plugins enable ai-passport-hermes
```

在当前档案已有的 `config.yaml` 中合并以下平台配置，不覆盖其他配置：

```yaml
gateway:
  platforms:
    ai_passport:
      enabled: true
      extra:
        host: 127.0.0.1
        port: 18790
        speech_language: zh
        realtime:
          enabled: true
          api_key_env: OPENAI_API_KEY
          model: gpt-realtime-2.1
          voice: coral
          output_gain_db: 0
```

没有重要任务运行时，再按 Hermes 的常规方式重启网关加载插件。本插件不会修改核心、
自动重启或升级 Hermes。不同档案需要使用不同端口。网关仍会执行自身的授权检查；
只有传输层验签并配对成功的设备才会获得适配器的授权标记，模型工具审批仍由 Hermes 管理。

`speech_language` 可设为 `zh`、`en` 或空字符串（自动检测）。通过 Hermes 的
`pre_transcription` 钩子仅影响工牌录音，不修改全局语言设置。实测本机 Whisper base
会将短中文样本自动误判为英文；明确指定中文后可恢复中文识别，但部分专有名词仍有错字。
协议接通不代表识别质量已经解决。

实时通话为可选功能，需要具有对应实时语音和转写模型访问权限的 OpenAI 账户，
会单独产生模型用量。除环境变量外，也可用 `api_key_file` 指向仓库外权限为 0600、
非符号链接的私有文件。密钥只保留在主机，不写入工牌。服务端使用 24 kHz PCM，
工牌沿用有界 IMA 传输，不增加固件缓冲。Hermes 原有文字模型和提问语音识别保持不变。

`output_gain_db` 可在主机上提升通话播放音量（0–12 dB，默认 0）。编码给工牌前用软限幅
保护较强峰值，不改变音频时序、麦克风增益或设备音量设置。扬声器偏小时从 3 dB 开始；
限幅只能避免数字溢出，不能防止实体扬声器失真，出现刺耳或沙哑时应降低增益或设备音量。
此项不影响其他 Hermes 平台，也不增加设备缓冲。

通话支持双向语音、字幕、语音及按键打断、播放确认、主动挂断和连续多轮。
打断由设备的回声确认检测及按键控制；上游 VAD 保留自动轮次检测，但不独立取消或清空播放。
工具请求使用 Hermes 原生会话和审批，实时模型不能虚构执行结果。挂断取消本通话
正在等待的委托，不取消其他设备任务。同一设备不能同时提问和通话；每次通话最长
一小时，主机播放缓冲上限为 2 MiB。设备合成音频测试只能使用本设备的
`-synthetic` 会话，不能执行工具。

## 安全入口与配对

将已有 TLS 隧道或反向代理指向 `http://127.0.0.1:18790`，支持 WebSocket 升级。
不要把 Hermes API 服务或此监听端口直接暴露到公网。使用有效且受信任的证书，并
保留 `/` 和 `/passport/v1` 路径。明文 `ws://` 仅允许回环地址本地测试。
带浏览器 Origin 的 WebSocket 请求会被拒绝。

使用与网关相同的档案目录生成配对码：

```sh
python3 <plugin-directory>/passport_auth.py --home <active-hermes-home> pair \
  --url wss://gateway.example
```

输出 JSON 含有 `gatewayUrl`、`setupCode`，兼容当前 Web Studio 的配对输入。
粘贴完整 JSON，将助手显示名设为 Hermes 等名称，再保存配置到设备。
配对码十分钟内有效，只能使用一次。它属于凭据，不要放进公开问题、截图或 CI 日志。

撤销设备授权时使用公开的 SHA-256 设备 ID：

```sh
python3 <plugin-directory>/passport_auth.py --home <active-hermes-home> revoke <device-id>
```

撤销后，已有连接上的新请求和回复推送也会被阻止。已经接受的 Hermes 任务可能继续
完成；撤销授权不会撤回工具操作。重新配对会轮换设备凭据。

## 语音、会话与失败处理

1. 设备使用 Ed25519 签名响应随机挑战。一次性配对凭据交换为独立设备凭据，主机只
   保存凭据哈希。
2. “提问”沿用现有的 16 kHz 单声道 mu-law 分片录音。适配器校验格式和大小，修正
   流式录音临时 WAV 长度，再调用 Hermes 已配置的语音识别，不需要另一份 API Key。
3. `passport.transcript` 提供识别文本回显。识别结果作为普通用户文字进入原生
   Hermes 会话，不当作网关斜杠命令。回答沿用现有设备聊天协议。
4. 通过 Hermes 的 send/edit 回调接收回复草稿和最终文本，是否流式由原生网关决定。
   第二次提问沿用该设备的 Hermes 会话，断线重连不会自动新建对话。
5. 已记录的请求 ID 在重连和适配器重启后仍会去重。中断中的任务标记失败，不自动
   重复执行；设备可通过历史查询取回已完成的回答。

设备取消操作会调用该会话的 Hermes 原生 `/stop`，不停止整个网关或其他设备。
取消后，识别线程可能仍需完成，但其结果不会提交给 Agent。暂时不能在工牌上响应
交互式工具审批，适配器不会自动批准。

监听器最多接受四个连接、四个并发问题，每台设备同一时间一个。录音限制与固件一致，
最长三十秒。回复快照限制 4 KiB，识别预览限制 479 个 UTF-8 字节。最多保存 128 条
近期请求回执，新问题到来时清理超过二十四小时的已结束回执。Hermes 自己维护完整
会话历史。临时录音以私有权限存储，处理结束后删除。
历史回复优先保留最新回答，总 JSON 不超过 5,500 字节，避免超出固件接收上限；
更早的对话仍保留在 Hermes 会话中。
私有目录 `<active-hermes-home>/passport/` 保存设备授权和近期识别、回复，
请按自己的隐私策略备份或删除。

## 验证与后续范围

在安装了两项声明依赖的临时 Python 环境中运行协议与安全测试：

```sh
python3 tests/test_passport_hermes.py
python3 tests/test_passport_hermes_talk.py
```

在真实 Hermes Python 环境中运行同一套测试，还会验证真实适配器和 WebSocket 生命周期。
`tests/test_passport_hermes_live.py` 是显式启用的真实模型测试：需要
`PASSPORT_HERMES_LIVE=1`、名称为 `passport-hermes-live-*` 的临时档案及可用模型。
它会产生模型用量，绝不能指向生产档案。

已验证：协议与安全测试、真实 Hermes 插件发现、签名设备回环问答、重连请求去重，
以及真实模型两轮问答的上下文连续性。合成中文语音在限定语言后，也已完成识别、
文字回显和真实模型回答；这不代表实际麦克风识别准确率已经验证。实时主机测试覆盖
真实模型两轮中文语音、原生 Agent 委托、编解码一致性、播放打断、撤销和挂断清理。
尚未验证：真实麦克风准确率、声学回声和打断质量、多档案运行及未来版本升级。
Web Studio 后端选择及独立 Hermes 分发包已纳入 v0.7.0；维护者确认最终实机回归及语音打断通过后发布。

实机验收还通过设备麦克风和扬声器完成了两轮中文语音，听者确认听到了算术答案。
通话持续超过五分钟且采集无丢帧；麦克风静音后没有产生新的输入轮次，挂断后返回首页，
未出现分配失败且堆完整。后续实机通话也完成了原生 Agent 委托和结果播报，按键打断后
连接仍保持。听者反馈初始音量小，提升 6 dB 后偏沙哑，因此部署已降至 3 dB，降低后的
主观音质仍需听者验收。这些结果不代表一般场景的识别准确率、声学回声或语音打断质量
已获得充分验证。
