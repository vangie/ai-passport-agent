# AI Passport Agent — OpenClaw 插件

## 项目组成与分发

本目录是 `ai-passport-agent` 开源项目正式维护的 OpenClaw 插件源码，
与固件和配置端沿用同一份 [MIT 许可证](LICENSE)。源码在本仓库维护，
不是私人主机里的脚本，也不依赖 OpenClaw fork。插件运行在网关电脑上，
固件运行在 Passport 上，所以安装位置不同，但属于同一个开源项目。
插件不内置私人网关地址、助手名称、账户、网络或凭据。

在仓库根目录，准备 Node.js 22 或更高版本、npm、Python 3 和 Make：

```sh
make plugin-test
make plugin-package
```

测试和打包不需要 ESP-IDF、硬件、正在运行的 OpenClaw、模型凭据或麦克风。
版本化源码包输出到 `build/openclaw/ai-passport-openclaw-<version>.tgz`。
打包使用明确的文件白名单，仅包含运行源码、迁移／检查工具、双语说明和
许可证，不包含依赖目录、缓存、本机链接、网关配置或密钥。打包回归检查
真实压缩包的内容与 JavaScript 语法。仓库中的锁文件固定源码安装所需的
传输依赖，不会另装第二套 OpenClaw 网关。

独立的[插件 CI](../../.github/workflows/openclaw-plugin.yml) 在 Node 22、24、26
安装锁定依赖、测试和打包，并把安装包保存为 CI 构件；不会发布 npm、创建
Release、连接网关或刷入固件。仓库完整门禁也包含同样的打包回归。
固件和插件可以独立升级；修改共享通信协议时需要配套更新，并在发布前验证
所支持的 OpenClaw 版本。打包测试不能代替真实网关 SDK 兼容验证。

## 可升级的原生接入

### 设备待机

闲置 60 秒后，Passport 关闭背光、让 LCD 进入可恢复休眠，暂停 LVGL 时钟和
按键组件的轮询，并释放应用的全速及禁止休眠锁。启用 ESP-IDF 自动浅睡眠和
Wi-Fi 调制解调器省电；应用仍每 50 毫秒检测一次 ADC 按键。这是保持连接的待机，
不是深睡或关机，当前页面、内存中的对话和已存配置都保留。任意功能键唤醒屏幕，
这次完整按下及松开只用于唤醒，不会误录音、发送或修改设置；下一次才执行界面动作。

录音、通话、发送及取消、网关工作、设置页面、正在配置和已枚举的 USB 主机连接时
保持唤醒。蓝牙连接或
配置命令会唤醒屏幕。USB 身份查询和只读诊断不会不断刷新闲置计时；执行 USB
命令时持有电源锁，已枚举的 USB 主机还会通过 ESP-IDF 的 USB 安全锁阻止自动
浅睡眠。`POWER` 诊断返回息屏、闲置时长和 USB 主机状态，不返回凭据或麦克风数据。
电源锁状态不等于实测电流。BSP 未提供可靠的充电状态，USB 主机连接和电量百分比
都不被当作充电检测。普通充电器无法用此方式识别，仍按电池供电的闲置时间息屏，
不会中断硬件充电；纯电池待机
电流和续航仍需实物测量。

验证检查点（2026-11-09）：完整仓库检查及待机策略、电源锁所有权、显示回滚测试
通过。应用 SHA-256 为
`8bdd6e7d2fb210fea88e36a7a004ac938d35209c3028c766026332434be11402`，
匹配 ELF 为 `ce6888d41b294fc135f62bc93e3b997bcdd73d4efaf4460d2fbd558fc4ad0b57`，
校验后只刷应用区，保留配置。74 秒 USB 主机实测超过息屏时间仍保持唤醒，配置
版本号及条目数量未变，堆完整性正常、无内存分配失败，并可进入设置、返回首页。
前一构建在加入 USB 主机保护前验证了息屏和首次输入只唤醒。最终版本的纯电池
休眠、实物按键唤醒、音频及电流仍未验证，USB 测试不能替代这些验收。

### 提问模式的语音回显

插件通过公开提示词钩子读取 OpenClaw 已生成的录音转写。配套固件按“你／助手”
顺序显示问题与回答：你的消息靠右、浅青色，助手靠左、浅白色；助手有配置名称
就显示名称，没有才显示“助手”，长名称省略显示，不缩小正文字号。
设备内存中保留最近三轮，继续提问不会覆盖上一轮。
长对话用按键翻页，默认打开最新一轮；如果当前仍在最新页，流式回复会自动跟到最后，
手动翻到旧页后不会被强行抢回。
记录不落盘，重启或切换助手时清除，也不等于网关的会话上下文。重试更新同一轮，
取消或重录会移除未完成的一轮，发送状态和错误提示不会混入回答。不会再做一次识别，
也不会让回答模型猜测录音内容。`passport.transcript` 沿用原生设备认证和会话
访问检查，同时匹配会话、请求和运行编号，不会返回其他轮次的最新转写。
进程内存最多保存 32 条短转写（每条最多 479 个 UTF-8 字节），十分钟后过期；
插件不会把这些转写落盘或写入日志。重新录音和取消只清除当前回显，不清除已完成问答。旧网关
没有此方法时仍能正常提问，只是不显示转写。

提问的识别由 OpenClaw 网关的音频模型完成，不是工牌本地识别。中文使用时，建议在
网关明确锁定中文，并给转写模型一个“保留专有名词”的提示；否则自动语言检测可能把
短中文误判成英文，地名、人名和产品名尤其容易出现同音错字。可在 OpenClaw 配置中
加入：

```json5
{
  tools: {
    media: {
      audio: {
        enabled: true,
        language: "zh",
        prompt: "请准确转写普通话，保留人名、地名、产品名和英文专有名词，不要翻译或改写。"
      }
    }
  }
}
```

也可以用命令设置：

```sh
openclaw config set tools.media.audio.language zh
openclaw config set tools.media.audio.prompt '请准确转写普通话，保留人名、地名、产品名和英文专有名词，不要翻译或改写。'
```

设置后重启网关，再运行插件 `doctor`；输出中的 `askAudio.language` 应为 `zh`，并且
`askAudio.promptConfigured` 应为 `true`。这只影响提问录音的转写提示，不会把密钥写入
固件，也不会改变通话使用的实时语音模型。若仍有错字，优先检查网关实际选中的音频模型
和日志，再调整模型，不要先改屏幕或重复刷固件。

提问开始录音时就准备网关认证连接，已配对设备会边录边上传音频，录音结束后才
提交完整请求。检测到至少约 240 毫秒语音后，停顿约两秒会自动触发与按键相同的
发送流程。起始静音、短促点击声和编解码器启动瞬态不会触发静音自动提交。
这是轻量本地能量检测，不是语音识别；周围人声或强噪声可能影响效果。取消或重录
会使队列中的旧自动发送事件失效。按住录音页面的按键时暂缓自动发送，松开后
按原动作处理。按键保留原动作和录音编号，避免自动发送后迟到的“发送”被解释成
“取消”。通话模式不变，仍可按键立即发送。

Wi-Fi 和助手设置用列表展示可切换项，不再一次只显示一个。光标高亮正在浏览的
选项，下方显示连接或使用状态；浏览不会直接改变当前网络或助手。Wi-Fi 有明确的
添加入口，长列表跟随光标移动并显示当前位置。长名称省略显示，不缩小字号。
列表复用聊天行控件，不额外分配一套 LVGL 对象。

需执行一次
`openclaw config set plugins.entries.ai-passport-openclaw.hooks.allowConversationAccess true`
并重启网关，允许插件读取会话内容。实现只提取 Passport 会话中的录音转写提示词。
按照 OpenClaw 的会话参与权限规则，转写 RPC 需要 `operator.write` 和已认证的
用户身份；此 RPC 本身不会修改会话。

0.3.0 用独立插件替代安装目录补丁：`passport-realtime` 提供方、
`/passport/v1` WebSocket 入口、需要认证的 `passport.status` RPC。
运行时仅导入公开插件 SDK，不依赖生成的文件名、私有导出或修改安装文件。
已验证基线为 OpenClaw 2026.10.5；未来版本仍需兼容检查。

通话打断保留已认证的 WebSocket 和对话。上键静音／恢复麦克风，中键打断
回复或等待中的请求（仅连接失败时变成重连），下键结束通话。按键和本地语音
检测共用原生 `talk.session.cancelOutput`，原因是 `barge-in`，不修改 OpenClaw
核心。传输层在取消期间丢弃旧音频和旧回复文本，并保留下一轮的麦克风输入。
麦克风静音时不启用语音打断，按键打断仍可用。
Passport 提供方关闭上游自动音频打断：由设备完成回声确认后的语音打断及按键打断。
服务端 VAD 仍检测说话结束并开始回复，但不能独立取消扬声器输出。
此策略只影响 Passport 通话，不改变其他客户端。
网关诊断只保留有界的回复状态、原因与错误码字段，不记录转录内容、入口地址或凭据。
连接中也可通过上键静音，音频启动保留此选择；静音输入以静音音频发送，
不会关闭助手的扬声器。连接阶段显示“正在连接”，不再显示录音提示。
下键可结束连接中或已接通的通话。物理按下／抬起事件由按键驱动独立入队，
不依赖界面／网络轮询，抬起时只执行一次操作，长时间按住也一样。
待机后的首次唤醒按键会被消耗，不触发通话操作。

C3 使用独立、有界的收音／播放环形缓冲和少量扬声器参考历史。持续的麦克风
信号与近期播放信号不强相关时，先短暂静音播放进行确认；回声消退后仍有语音
才触发打断，并保留确认语音最后 32 毫秒再恢复收音。这是带回声判断的打断
检测，**不是完整声学回声消除**，也不是持续全双工转录。噪声、房间混响、
佩戴位置和音量仍需实机验收，合成测试不代表真实声学准确率。候选被否决时
可能短暂降低播放，但不取消回复。新增缓冲只在通话期间分配，不与提问录音并存。

提供方暴露仅作用于当前通话的 `passport_end_call` 工具。明确说“挂掉吧”、
“结束通话”或“我不想聊了”，会关闭当前语音会话、停止音频接收，并通过原生
会话清理收尾本次通话中的待处理任务；不会关闭网关或影响其他通话。
取消任务、静音、引用示例和“不要挂断”不属于挂断指令。由语音模型判断并调用
工具，不使用转写关键词匹配。配套固件把正常结束视为成功，释放音频并回到
首页；意外断线仍提示可重试错误。更新插件后重新进入通话即可使用挂断工具；
正常返回首页需要更新配套固件。

原始设备挑战、签名、角色、权限和令牌原样交给本机原生网关校验，
不使用服务端／管理员凭据或伪造调用者。HTTP 路由采用插件认证，因为
真正认证在原生 WebSocket 握手中，不新增 HTTP 密码。未认证客户端不能
调用 RPC。不信任客户端转发头，上游转发不会被视为本机直连。保留原有
网关暴露／代理策略。连接数、认证等待、帧、待确认请求、套接字积压和音频
队列均有上限；停止插件关闭两侧连接。

设备撤销、会话权限、历史和工具确认仍由原生 OpenClaw 管理。包装提供方
继承官方已配置提供方的模型、声音和助手范围内凭据，不复制密钥。保留
原生直接回答、查询／控制工具、中英文策略、IMA 压缩、播放节奏和执行中／
最终工具结果区别。其他客户端保留原提供方／入口。全局配置了
`force-agent-consult` 时明确拒绝，不偷偷修改。

安装到网关软件包以外的固定位置：

```sh
cd /path/to/ai-passport-agent/tools/openclaw
npm ci --omit=peer --ignore-scripts
openclaw plugins install --link --accept-capabilities /path/to/ai-passport-agent/tools/openclaw
node doctor.mjs
openclaw gateway call passport.status --json --params '{"agentId":"passport"}'
```

Node 必须能解析宿主的 `openclaw/plugin-sdk/*`。如果无法解析全局包，把
已有宿主包链接到 `node_modules/openclaw`，不要另装第二套网关。doctor
检查公开 SDK 和原生握手，创建／关闭未连接模型的桥接对象，不启动麦克风、
不导出凭据。状态 RPC 可用 `agentId` 在运行中的网关检查对应助手凭据就绪。

用压缩包安装时，将其解压到网关电脑的固定目录，在该目录执行
`npm install --omit=peer --ignore-scripts`，再将该目录传给同样的
`openclaw plugins install --link` 命令，无需先发布 npm。模型凭据和可访问的
网关仍通过 OpenClaw 自身配置，本项目不分发这些数据。状态命令示例中的
`passport` 应替换成自己的实际助手 ID。

升级源码安装时，保留上一可用版本，更新插件源码，重新执行
`npm ci --omit=peer --ignore-scripts`，通过 OpenClaw 现有服务管理方式重载／
重启，再运行 doctor 和状态 RPC。不要把插件放进 OpenClaw 安装目录，
也不要重新应用旧核心补丁。

经本机回环转发需要现有网关可信代理策略允许该本地转发节点，不自动放宽策略。
迁移要求没有活动的 Passport 连接。通话关闭时丢弃排队音频，拒绝迟到事件，
之后才允许复用同一连接创建新通话。
转发端校验原生事件连续性，再为筛选／合帧后的下游事件分配连续序号；
原生事件真的丢失时仍会失败，不通过重编号掩盖。

首次迁移先保留旧固件，再执行：

```sh
python3 manage-plugin.py inspect --dist /actual/openclaw/dist
python3 manage-plugin.py migrate --dist /actual/openclaw/dist
```

迁移校验旧补丁回执／原始备份，保存带校验和的回滚目录，还原官方处理器。
不会自动重启或更改网关配置。通过现有服务管理器重启一次，再刷协议 1 固件。
仅“通话”在已存网关路径后追加 `/passport/v1`，“提问”和配对仍用原入口。
已存地址、代理和设备凭据无需重填。缺少协议标记时在开始录音前明确失败。

以后升级 OpenClaw，再跑 doctor 和状态 RPC，不再重打旧补丁。SDK、提供方
或协议不兼容会明确报错。插件在自己的目录／软件包内独立更新，正常重载／
重启；保留上一个可用插件包。旧补丁需显式回滚，脚本拒绝覆盖升级后的处理器：

```sh
python3 manage-plugin.py rollback --dist /actual/openclaw/dist --backup /saved/rollback-directory
```

回滚旧补丁后重启并恢复使用根路径的上一版固件，不要把旧补丁恢复进新版
OpenClaw。合成会话就绪／关闭和主机测试，不代表实机音质或新闻结果播报验收。

## 旧补丁参考

这是针对所检查 OpenClaw 2026.10.5 网关的可选、带版本检查的补丁，
不是固件依赖，也不是已合入上游的修复。普通 OpenClaw 客户端不变；
不修改网关认证、凭据、网络入口、Agent 配置或工具权限。

对签名设备类型为 `ai-passport` 的已认证客户端：

- 将工牌选择的通话语言同时用于提供方对话指令、强制查询的回复风格、等待确认
  和最终口播。`zh`／`zh-*` 使用普通话及简体中文字幕，`en`／`en-*` 使用英文；
  用户明确要求切换语言或翻译时仍可切换。上游 `language` 参数只影响输入转写，
  并不限制回复语言。保留已有角色／工具指令，不影响其他设备类型或未指定的
  语言。安装修复后结束旧通话再进入即可，不必重刷固件。
- 普通对话和常识由实时模型直接根据音频回答，不再等待最终转写，也不再每句
  强制查询 Agent。保留所配置助手的人设，以及查询和控制工具。实时信息、工具、
  操作、私有记忆、工作区及跨会话状态仍通过 Agent 查询，参数应带上本次通话的
  相关上下文。这是模型自主分流，不保证每次分类正确；语音不明确时应简短追问，
  不得将工具失败说成执行成功。现有工具权限和确认检查不变，其他客户端仍使用
  原有查询策略。更新后退出并重新进入通话即可，无需重刷固件。
- PCM16／24 kHz 回复合并为最多 80 毫秒一帧；不足一帧最多等 20 毫秒，
  遇到播放标记、字幕或回复边界先发完尾帧。按每毫秒 48 字节下发，允许
  PCM 提前 160 毫秒，协商后的 IMA 提前 800 毫秒。仅在工牌传输上移除重复 `talkEvent` 元数据和输入
  音频回显事件；网关历史、控制消息与上传确认不变。
- 精简传输仍保留工具结果元数据中的 `type` 和 `final`。执行中或部分结果
  不能结束工牌正在等待的任务，否则后续聊天完成结果就无法交回语音提供方。
  其余重复工具元数据继续省略。此修复只涉及网关，重新进入通话即可，
  不需要重刷工牌。
- 建会话时声明 `passportSilence`。只有协商成功，完全为零的输入帧才可用
  `audioBase64: "passport-silence:<字节数>"` 表示；网关将 2–3,840 的偶数
  长度还原为相同 PCM，再交给既有桥接。采集节奏、时间戳、VAD 时间连续性
  不变；普通音频及未装补丁的网关仍传 base64 PCM。这是私有兼容扩展，
  不是上游 base64 编码，也没有新增免鉴权入口。
- 服务端队列限制为 6 MiB PCM、20,000 个事件。超限明确结束通话；取消
  丢弃排队音频，关闭会话时停止计时器并释放引用。
- 仅当已认证工牌声明 `passport-ima-v1` 时协商 `passportIma`。双向通过
  `passport-ima:<base64>` 传 IMA ADPCM：六字节的小端预测值／索引／保留位／
  样本数字段，加上低半字节优先的编码，每块最多 480 个样本。四个完整块共
  984 字节，而原 PCM 为 3,840 字节。校验所有边界，输入先还原 PCM 再交给
  既有提供方桥接。这是有损私有扩展，不改提供方格式或采样率；未更新的
  客户端／网关保留原 PCM 路径。

OpenClaw 可能比工牌播放速度更快地产生回复。没有节拍控制时，小播放环会
让共享 WebSocket 暂停收包，排在音频后面的上传确认即使网关正常也会触及
十秒期限。只增大超时或设备内存不能消除这种队头阻塞。工牌使用
10,336 字节播放环，PCM 约 215 毫秒、预缓冲 160 毫秒；IMA 使用
42 个 246 字节固定槽，约 0.84 秒、预缓冲最多 640 毫秒。合并帧仍通过既有
960 字节网关暂存分段解码。播放使用 246 字节局部临时区；独立的 3,624 字节
压缩收音环（27 个 256 样本 IMA 块，288 毫秒）和有界回声参考／检测状态
让本地打断不会覆盖播放数据，相比半双工方案增加约 4 KB、仅限通话期间的
堆内存，不增加任务栈。拉取时解码 PCM，再按协商的上传帧编码，因此增加一次
有损编码，收音质量、CPU 和堆余量仍需实机验收。上传在已有分配的空闲区
先编码再整体 base64，兼容尾部不满块。
八槽播放确认队列满时，仅合并队尾严格递增的 `audio-N` 标记；提供方确认是
累计式的，必须等替代标记对应的全部 PCM 播完才确认，任意名称的标记不合并。
重连仍由用户明确操作。按时钟节拍下发不等于按实物播放确认发放
额度，不能保证任意网络卡顿下声音都连续。

节拍化输出携带独立的 `playbackSequence`。匹配固件将播放去重与输入事件
序号分开，否则更新的输入事件可能让刻意延迟的音频被误判为旧包而丢弃。
没有该字段的旧网关仍使用原序号处理。对补丁网关测试通话前先装匹配固件。

播放在短于 10 毫秒的包间隔内保持已预缓冲状态，该间隔小于 24 kHz 下约 21
毫秒的 I2S DMA 窗口。之前软件环形队列一空就重新预缓冲 160 毫秒，即使 DMA
内仍有可播放数据，普通包抖动也会变成明显停顿。更长的断流和新回复仍采用有界
预缓冲，重新缓冲时不扩大播放环或任务栈分配。确定性音频测试覆盖
5 毫秒补包不重新预缓冲、60 毫秒中断后有界重新预缓冲；实物扬声器连续性仍需验收。

声音在网关上配置，不编译进工牌。例如
`openclaw config set talk.realtime.providers.openai.voice coral` 为新建的 OpenAI
实时会话选择 Coral。此设置作用于该提供方，并非单独覆盖某个助手，也不会改变已经
输出语音的会话。模型和凭据保持不变。

## 安装与恢复

将本目录复制到网关主机，使用实际安装的 OpenClaw `dist` 目录，不猜全局包位置。

```sh
python3 install-passport-relay.py /path/to/openclaw/dist
python3 install-passport-relay.py /path/to/openclaw/dist --apply --expected-sha <dry-run-original-sha>
```

安装器要求匹配预期源码边界，并检查补丁 JavaScript 语法；原文件按校验和
备份在 `.passport-relay-backups/`，同时保留处理器、中继及编解码模块 SHA-256
的安装回执。同一补丁重复安装
不做修改，发现意外更改则停止，不覆盖。安装后用既有服务管理器重启网关，
重启会中断当时的网关连接。

明确回滚：

```sh
python3 install-passport-relay.py /path/to/openclaw/dist --restore
```

恢复后用同一服务管理器重启。OpenClaw 升级可能替换处理器或模块，升级后
不能盲目重放本补丁，须重新检查版本相关的集成边界。
